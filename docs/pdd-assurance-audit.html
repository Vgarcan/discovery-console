What the PDD draft really says

The draft read well, and that was the thing worth checking. This review traced every path from a captured fact to a rendered template field, measured how much of the Velera PDD the console can fill at its best, and records what was done about it.

the headline that started it

33 of 34

Of the template cells left empty by the sample session, all but one were empty because no capture path existed to fill them. The Location, Owner and Provider of every input and output; Access Granted and User Details for every system; a contact for every person — written as TBC in the source, unconditionally.

The document contract says a TBC is an unanswered question. For these it meant something else: a question the console never asks. Nothing in the output told them apart, so an analyst could not tell which TBCs to chase.

They are now marked TBC — same word, dashed outline, counted separately in the header and written TBC (by hand) in the Markdown. The thirty-three still cannot be captured; they can now be seen.

High severity

Four findings where the output was wrong or silently incomplete, rather than merely coarse. All four are closed.

PDD-01 High Closed 04-capture.js · 01-model.js

The capture buttons and the PDD spoke different vocabularies

Pressing a type in the quick-type grid seeded the item with the button's label: tags: seed ? [seed] : []. The PDD looked up the tag vocabulary declared beside it in 01-model.js. In seven of the nine areas those two lists disagreed.

AreaButton wrotePDD looked forField that emptied
OperationsAverage volumeVolume1.3 Expected volumes
OperationsPeak volumePeak1.3 Expected volumes
ProcessEnd conditionEnd2.1 Result / end state, 2.3 flow
EvidenceSOP / documentSOP2.2 Available references
SystemsAPI / ServiceAPI1.4 Access Type
SystemsRemote / VDIRemote1.4 Environment, Access Type
SystemsCustom buildCustom1.4 Owner
…and 5 more: Approval rule, Upstream process, Downstream process, To verify, Unclassified

Re-tagging the sample session the way the grid would have written it — same facts, same areas, captured live instead of through the detail sheet — took the draft from 25 of 28 down to 23 of 28. The sample session could not expose this, because all 53 of its items were tagged from the canonical list, and the 110-check suite asserts against that same file.

Fixed An action is now [label, description] or [label, description, tag], and tagOf() is the single place the two are reconciled. Both seeding paths go through it. A new rule in tools/audit.py fails the build if any capture type resolves to a tag its area does not declare — verified by deliberately breaking one. A grid capture and a sheet capture of the same facts now produce an identical draft, 93 of 94 either way.
PDD-02 High Mitigated 16-pdd.js

TBC carried two meanings and the reader could not separate them

Thirty-three cells were written as the literal TBC constant with no data path behind them: 1.2 Contact (4), 1.4 Access Granted and User Details (8), 2.5 Location, Owner and Provider across inputs and outputs (18), plus the three 1.3 fields that are deliberately not the analyst's call. Three carried an explanatory hint; the other thirty rendered identically to a field the client simply did not answer.

Mitigated, not closed A second sentinel NA now marks them. They render as TBC with a dashed outline and a tooltip, read TBC (by hand) in the Markdown, and are counted on their own line in the header rather than against the evidence score. The console still cannot capture them — giving per-item fields to inputs, outputs and systems is a feature, not a fix, and is the natural next piece of work.
PDD-03 High Closed 16-pdd.js pddMarkdown()

One reply could destroy a Markdown table

Table rows were joined with " | " and nothing escaped the cell contents. Replies are free text from a textarea where Shift+Enter inserts a newline, and they are the source for twelve PDD outputs — every Description, every business action, every URL/Details cell. A single | shifted every cell after it; a single newline split the row in two and the renderer dropped both halves.

was  | 1 | System exception | Gateway token expired | Pause the run | then retry
     Escalate if it repeats |
now  | 1 | System exception | Gateway token expired | Pause the run \| then retry<br>Escalate if it repeats |
Fixed Table cells escape the pipe and turn newlines into <br>, which keeps the value inside its cell. Field values and list items flatten newlines to a space, so a bullet stays a bullet. A check in the suite asserts every emitted table row keeps its column count.
PDD-04 High Closed 17-transfer.js importMerge

Merging a session silently discarded every relation in it

The remap rewrote each targetId to its new id, then filtered the rewritten rows against map, which is keyed by the old ids. map[newId] is always undefined and S.items had not been concatenated yet, so the test failed for every relation. Replaying the merge branch against the sample file: 21 relations in, 0 out.

was  .map(r => ({...targetId: map[r.targetId] || r.targetId}))
     .filter(r => map[r.targetId] || ...)      // tests the NEW id
now  .filter(r => map[r.targetId] || ...)      // tests the ORIGINAL
     .map(r => ({...targetId: map[r.targetId] || r.targetId}))
Fixed Filter on the original target, then rewrite. 21 in, 21 out, no dangling targets. The suite's "merged relations still resolve" check passed vacuously before, over an empty list; it now has something to check.

Medium severity

Findings where the numbers on screen overstated what the document could support.

PDD-05Medium Closed 16-pdd.js pddStats()

A table counted as filled if any one cell in it had content

pddStats() scored each table as a single unit: b.rows.some(r => r.some(c => c && c !== "")). Section 1.4 with four system names and sixteen empty cells scored the same as a fully evidenced one. The gap between the two readings was the gap between 25 of 28 (89%) and 93 of 127 (73%).

Fixed Every cell is scored on its own, and the by-hand cells are out of the denominator. The sample session now reads 93 of 94 fields carrying captured evidence alongside 33 the console cannot ask for. Version Control and Sign Off stay excluded, as they always were.
PDD-06Medium Closed 10-review.js

Review coverage counted items, not evidence

pct = Math.min(100, n * 25), where n was the item count in the mapped areas. Four Process items all captured as Flow cue put "2.1 Process description" at covered / 100%, while the PDD rendered Business purpose, Trigger, Result and Principal systems as four TBCs.

Fixed Coverage is computed from the real per-section fill via a new pddSectionFill(), and each row shows the fraction. A section with items captured against it but nothing reaching a field now reads not landing 0/4 instead of covered.
PDD-07Medium Mitigated 01-model.js GAPS · 16-pdd.js

Answering a control question could not move the field it names

Thirty-nine control questions drive the coverage meters. Several name a PDD cell that has no data path, so ticking them raised the meter and changed nothing downstream: Confirm access and authentication (1.4 Access Granted, User Details), Confirm where each input arrives and who provides each input (2.5 Location, Provider), plus three that name no column at all — the purpose of each system, the cause of each exception, retry and escalation behaviour.

Mitigated, not closed The cells those questions name are now visibly by-hand, so the disconnect is legible rather than silent, and the Review coverage bar no longer inherits the meter's optimism. Closing it properly means either giving those questions a destination field or dropping the ones the template has no room for — a template decision, not a code one.
PDD-08Medium Closed 16-pdd.js 2.8 · 01-model.js

Section 2.8 credited Data for evidence Data could not give

2.8 collected byTag("Evidence","Report").concat(byTag("Data","Report")), but Report was neither a Data tag nor a Data capture type, so the second lookup could only ever match a hand-typed tag — while the coverage map listed 2.8 as drawing on ["Data","Evidence"], so every Data item raised that bar.

Fixed Report is now a Data capture type and tag, so the lookup and the coverage map agree. The new vocabulary rule in audit.py would have caught the reverse case.
PDD-09Medium Closed 16-pdd.js envOf

One tag filled two different template columns

Remote appeared in both the environment list and the access-type list. A system tagged only #Remote rendered Environment = Remote and Access Type = Remote. The analyst recorded an access method; the document reported an environment.

Fixed Remote belongs to accessOf alone. Environment falls back to TBC, which is the truth. This was the one place the "nothing is invented" rule was quietly broken.

Low severity

Worth fixing, none of them changed what the document asserted. All closed.

PDD-10Low Closed16-pdd.js 2.6

Exception Type was chosen by substring match over free-form tags

t.indexOf("exception") > -1 scanned every tag on the item, including ones the analyst typed: a tag reading "no exception path yet" would have been promoted to the Exception Type column, and one capitalised "Exception" would have been missed.

Fixed The lookup now matches against DEF.Exceptions.tags, the declared vocabulary. Unclassified, a capture type that had no tag at all, was added to it.
PDD-11Low Closed18-render.js

renderAll() did not repaint the PDD or the Review

The documented invariant is that any change to the session calls renderAll(), so a change to one view cannot silently skip another. It repainted six things and neither output view. Nothing was stale in practice, because both are only reachable from setView() — the invariant held by accident.

Fixed renderAll() repaints both when they are on screen, and the one-off renderReview() call inside toggleGap() that was papering over it is gone.
PDD-12Low Closed10-pdd.css

TBC lost its colour in the PDF, and the analyst's notes kept theirs

The TBC chip is a background fill with no print-color-adjust, so most browsers dropped it when printing — in the one artefact that goes to a client, TBC stopped being visually marked. Meanwhile the instructional hints ("Write this up as one short paragraph…") printed into the PDF.

Fixed print-color-adjust:exact on the chip, and .pdd-hint is hidden in print. The table notes that belong to the template — "Never record passwords here" — still print.
PDD-13Low Closed17-transfer.js

Import did not validate the area an item claimed

normalise() fixed ids, timestamps and reply arrays but never checked section against the nine areas. An item naming an unknown area was counted in the session totals and appeared on the tape, but reached no area rail, no review inventory and no PDD section, and nothing reported the discrepancy.

Fixed placeItems() parks a stray item in Systems, coerces a non-array tags or relations, and the toast says how many were moved. resolved entries are filtered to strings.
PDD-14Low Closed16-pdd.js

Two dead paths in the PDD module

allReplies() was defined and never called. printPddBtn added a printing class to the body that no stylesheet in the project matched, then removed it after a 60ms timer.

Fixed Both removed. The print button calls window.print() and nothing else.

What held up

Checked and found sound, so none of the fixes needed to disturb them.

  • Every value rendered into the PDD view passes through esc(). Item names, tags, replies, labels and table notes are all escaped — no injection path from captured text into the document.
  • Sign Off renders as genuinely blank cells rather than TBC, and is correctly excluded from the fill metric along with Version Control. The distinction the template asks for is respected.
  • Empty areas fall back to an all-TBC row rather than an absent table, so the template's shape survives a thin session.
  • Deleting an item strips the relations pointing at it, so the PDD never renders a dangling reference.
  • Section numbering and ordering match the approved template, including the two part headings and the fifteen numbered sections.

Method and limits

How the numbers were produced

Every module in src/js was read in full. pddModel(), pddStats() and the merge branch of importMerge were then ported line for line to Python and replayed against the shipped sample session — before and after each change — which is how the 127-cell count, the 33 unreachable cells, the 25-vs-93 gap and the 21 → 0 → 21 relation count were measured rather than estimated. The vocabulary drift in PDD-01 was computed by diffing each area's actions against its tags; that diff is now a build rule, and was verified by deliberately reintroducing one of the twelve.

What was not run

This machine has no JavaScript runtime and no Playwright, so tests/audit.test.js — now 130-odd functional checks, including new ones covering the two-step delete, the capture vocabulary, the by-hand count and the resize handles — has not been executed, and nothing has been exercised in a real browser. python tools/build.py and python tools/audit.py both pass. Run the suite and open the app before publishing.

Not in scope

Whether the template mapping matches the current approved Velera PDD is a question for the document owner, not for the code. This review checks that the console does what 16-pdd.js and the README say it does.
